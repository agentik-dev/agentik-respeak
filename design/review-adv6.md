# Adversarial review ADV6: this plugin as shipped

Reviewer: this repo's ADV6 relay row, claude-opus-5-5, on `main` `2a21d76`, 2026-09-23. `RS` abbreviates the plugin's name in paths and variables below (`RS-check.sh`, `.RS.yaml`, `RS_CONFIG`). Read: every script under `plugin/scripts/` and `scripts/`, `plugin/hooks/hooks.json`, the `Makefile`, the tests. Every reproduction below ran in a temp directory or a `git archive` copy; nothing in the checkout was edited except this file and the charter.

## Findings

**ADV6-1 (high, wrong green): a folder sidecar turns the gate and `make check` green.** `RS-config.py` lets folder layers set `gate.fail_on` and append `gate.allow` (line 92, `APPEND_LISTS`); `RS-check.sh` uses the same resolver, so `make doclint` obeys them. `.gitignore` ignores `.RS.local.yaml` everywhere, so the softening file can be invisible to `git status` and to review. Repro, temp repo with the gate on and `docs/a.md` holding two error hits: `RS-check.sh` gives `1 blocked`, rc 1; add `docs/.RS.yaml` with `gate: {fail_on: none}` and it gives `1 passed`, rc 0; the same with `allow: [".*"]`; the same with the file named `.RS.local.yaml` and ignored. Fix: the CI verdict (`--file` and `RS-check.sh`) reads `fail_on` and `allow` from the committed project layer only, and hygiene reports any sidecar that lowers `fail_on`.

**ADV6-2 (high, wrong green and live state): the environment and the session provider change the CI verdict.** `RS-check.sh:36` unsets `RS_GATE` and `RS_HOOKS` but not `RS_CONFIG`, `CLAUDE_CODE_SESSION_ID` or `XDG_STATE_HOME`; this session exports `CLAUDE_CODE_SESSION_ID`. A skipped file counts toward exit 0 (lines 137 to 140), with no floor. Repro: `RS_CONFIG=env.yaml` (`gate: {enabled: false}`) gives `0 passed, 1 skipped, 0 blocked`, rc 0; `XDG_STATE_HOME=state CLAUDE_CODE_SESSION_ID=s1` with a provider `2.0` file carrying `RS.gate.fail_on: none` gives `1 passed`. `tests/test_check.sh` and `tests/test_gate_hook.sh` scrub neither variable, so once the session plugin writes `resolved.json` the suite reads it. Fix: unset all three in `RS-check.sh` and the two suites; a skip whose reason is not a project `exclude` or an absent project config is a failure.

**ADV6-3 (high, wrong green): the README stamp is a sidecar a builder can move.** `scripts/readme-fresh.sh --stamp` hashes whatever README is on disk; the check compares hashes and never runs the verifier. Deleting `design/readme/source.md` reads `skipped`, exit 0. Repro in a `git archive` copy: append a sentence to `README.md`, `readme-fresh.sh` says `stale`; run `--stamp`; it says `fresh`, rc 0; `rm design/readme/source.md` gives `skipped`, rc 0. Fix: the check also runs `RS-verify-edit.py source README` (under a second), and a stamp without its source is `stale`.

**ADV6-4 (medium, wrong green): "prose-only" admits new claims and flipped claims.** `RS-verify-edit.py` md policy keeps headings, lists, links, code and numbers but not the paragraph count or polarity. The `make readme` contract says "add no fact, drop no fact"; only the prompt enforces it. Repro: source plus an appended paragraph "This plugin deletes nothing and is safe for production use everywhere." gives `PASS (md)`, rc 0; the first " never " replaced by " always " gives `PASS`, rc 0. Fix: paragraph count per section as an invariant, and a multiset of polarity tokens (not, never, no, without, always, only, must).

**ADV6-5 (medium, recursion and unbounded work): `RS-render.sh` has no wall clock, no group kill and no depth guard.** `run_agent` (line 151) waits on `claude -p` forever; killing the renderer leaves the runner alive. The runner inherits `RS_RENDER_CMD`, runs in the repo with its hooks and a `CLAUDE.md` that says "run `make readme`", and is limited by `--allowedTools` (an allow list; `--tools` restricts), with no `--max-turns`. A child that is permitted Bash can start its own ancestor, the D5 shape. `--max-rounds` is unchecked: `x` prints "still failing after x round(s)", rc 1, no round run; any large number is allowed. Repro: a runner that sleeps 300 s: renderer alive at 6 s; after `kill` of the renderer, `pgrep` finds 1 orphan runner. A recording runner shows cwd = the worktree and no depth variable. Fix: refuse when `RS_RENDER_DEPTH` is set, and export it to the child; `--tools Read,Grep,Glob --max-turns N`; spawn the runner in its own process group under a default 600 s wall clock and kill the group; `--max-rounds` in 1 to 5.

**ADV6-6 (medium): a failed `make readme` leaves the failed render in `README.md`.** The recipe renders with `--out README.md`; `git checkout -- README.md` runs only when the verifier fails, not when the render exits 1. Repro, a fake runner returning two banned phrases (`[ai_cliches]` hits): make exits 2, `git status` shows ` M README.md` with that text. Fix: render to a temp file; move it over `README.md` only after the gate and the verifier pass.

**ADV6-7 (medium): the hook gate fails open on a large file.** `hooks.json` gives the gate 20 s; on timeout the write stands, and the measure process is not in a group the kill reaches. Repro: an 11 MB Markdown file with one banned phrase, the gate hook takes 24.1 s (rc 2 when let finish); a 3.4 MB file takes 7.3 s. Fix: fail early: above a size ceiling (for example 2 MB), block with "too large to gate", and give measure its own deadline under the hook's.

**ADV6-8 (medium, wrong red and a missing rule): doclint refuses the relay's own `NEXT`, and lacks the D5 rule.** The relay prompt tells a sitting to write `history/sessions/NEXT` for a safe next phase; doclint's `next` rule refuses any file named `NEXT`. Repro: write `history/sessions/NEXT`, `scripts/doclint` exits 2 with `next: a NEXT file is present`. Its content (a prompt path) is never checked to exist. doclint has no rule for acceptance lines that run `relay plan|run|gate` without `--rows`, nor for `make check` as an acceptance line, which `design/packets/r6-resync.md` line 57 uses. Fix, in the canonical copy (the session plugin): allow `history/sessions/NEXT` when it names an existing packet, and add the D5 acceptance-line rule.

**ADV6-9 (high, public surface): owner paths and private names in the public tree, allowlisted.** Four `design/packets/rows-*.json` carry absolute prompt paths under the owner's home directory plus the owner's user name; the packets carry home-relative paths to sibling repos; three charters name a private repo. `.hygiene-allow` admits them (`design/packets/*: sibling,home,person`, `history/sittings/*.md: private`), so `scripts/hygiene --json` reports `home` 7 files and `hits_outside_allowlist: 0`. The absolute prompt path also points a worktree child at the root checkout's copy of its packet. Fix: rows name prompts repo-relative; drop `home` and `private` from the allow file. Whether relay rows and charters belong in a public repo at all is the owner's call.

**ADV6-10 (low): python probing costs a pyenv shim per call.** The cache (`RS-python.sh`) stores the name `python3`, the pyenv shim, not `sys.executable`; the candidate list still holds `/usr/bin/python3`. A gate call launches python about six times at 0.06 s each against 0.01 s direct; under the pyenv rehash lock of D5 (60 s waits) the 20 s hook fails open. Fix: cache the resolved executable.

**ADV6-11 (low, live state in tests):** `tests/test_check.sh` lines 122 to 123 gate the real checkout's docs (the D7 class; `make doclint` already does this); `tests/test_report_env.sh` cases 1 to 5 run the real `claude --version`. Fix: fixture repo and a fake `claude` on `PATH`.

**ADV6-12 (low):** when `mktemp` fails, `RS-render.sh:92` falls back to `/tmp/RS-render.$$` and its trap runs `rm -rf` on it; `RS-gate.sh` and `RS-check.sh` use the same predictable form. Fix: exit 2 when `mktemp` fails.

## Verdict

Not ready to gate the device project's repos as a gate other repos trust. The hook side is careful (whitelisted strings, overrides, fail-open by contract), but the CI side, the part a relay treats as proof, can be turned green without fixing anything: by an ignored sidecar (ADV6-1), by the environment or the session provider (ADV6-2), or by re-stamping the README (ADV6-3). Fix those three and ADV6-5 (the renderer is the plugin's only process that can spawn Claude) before the device project depends on it. ADV6-4, 6, 7 and 8 can follow in the next packet; ADV6-9 waits for the owner's ruling; 10 to 12 are hygiene.
